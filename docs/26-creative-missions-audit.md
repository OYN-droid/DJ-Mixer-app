# Creative Missions workflow audit

This audit reflects the implementation in `app.js`, `src/project-intelligence.js`, and `src/recommendation-engine.js` before Sprint 8.4. It records callable behavior rather than inferred product capability.

| Existing workflow | Domains | Trigger and state model | Preview / apply / undo | Failure handling | Reusable functions and missing integration |
| --- | --- | --- | --- | --- | --- |
| Auto Mix | DITC, Decks, Smart Mix, playback | Deck controls build `autoMixState.items`, `plan`, `index`, prepared deck, transition, timers, and manual-override state. | Plans render before playback. Apply starts the existing deck/transition pipeline. Stop and manual override cancel future work; there is no project-state rollback because playback is transient. | Empty source lists, unavailable decoded audio, load errors, transition cancellation, and manual overrides are represented in Auto Mix status and `lastError`. | Reuse the Auto Mix plan and transition controller. Missions must not schedule deck audio independently. Missing before Sprint 8.4: a durable goal/step wrapper and history. |
| Smart Mix | Decks, transition controller, tempo recovery, playback registry | Prompt or controls populate `smartPromptState`; `planSmartPrompt()` parses intent and builds a plan. | `generateSaferTransitionPlans()` and plan rendering provide review. `applySmartPromptPlan()` delegates execution to the existing transition controller. Cancel/manual override provide operational recovery, not historical undo. | Missing decks, stale/changed playback, unsafe BPM moves, execution errors, and cancellation are reported in Smart Mix state. | Reuse `planSmartPrompt()`, `generateSaferTransitionPlans()`, `selectSaferTransitionPlan()`, and `applySmartPromptPlan()`. | Mixtape Analyzer | DITC/reference files, Project Intelligence, Prompt Studio | `mixtapeReferenceState` stores reference inputs; `mixtapeInspirationState` stores analyzed structure and blueprint. | Analysis and blueprint render before `applyMixtapeBlueprintAsPlan()` creates an editable AI plan. Missing: direct, validated mapping from blueprint chapters to mission steps. |

## Duplicate logic found

- Beat, harmony, pad, and transition planning already had plan/preview/apply phases. Creative Missions should coordinate them and must not reproduce their generators.
- Recommendation and Prompt Studio already had context-version checks. The mission orchestrator needs the same rule at step boundaries, but owns mission status rather than recommendation status.
- Arrangement insertion existed in each producing domain. Mission rollback can store the returned/new clip ID rather than create another editor insertion model.
- Project decisions already flow through `recordProducerEvent()` and Project Intelligence. Mission lifecycle events should use that path instead of maintaining a second visible journal.

## Missing integration addressed by Sprint 8.4

- One normalized, persisted mission and step model.
- Draft, plan preview, guided apply, approved-step apply, advanced apply-all, cancellation, stale-step validation, partial completion, per-step undo, conditional full rollback, recent history, prompt commands, and recommendation-launched mission drafts.
- A UI-independent orchestrator configured with a DeckForge domain adapter.

## Known service gaps

- Pad-bank apply has confirmation but no durable full-bank rollback token.
- General Arrangement edits do not expose a whole-project transaction snapshot; mission-created clips are reversible by ID.
- Stem separation is not generated by Creative Missions. Remix and Mashup correctly show missing stem requirements until existing Stem Lab outputs are available.
- Energy comparison is unavailable without analyzed track/reference energy values; the mission does not invent a graph.
- Plan preview is always available. Audio preview is exposed only on steps backed by an existing registered preview source.
