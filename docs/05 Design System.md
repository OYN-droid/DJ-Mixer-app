# Design System

The DeckForge interface should feel like a professional instrument, tactile, focused, and legible in a dim room. Visual character supports performance without competing with it.

## Color

- **Matte black and charcoal** form the application shell, work surfaces, and equipment panels.
- **Orange and amber** identify primary creative actions, selected regions, and important editable focus.
- **Purple** identifies AI planning, suggestions, and generated candidates.
- **Cyan** communicates playback, monitoring, focus, and active audio feedback.
- **Green** communicates healthy active states, loops, successful application, and ready status.
- **Red** communicates recording, clipping, destructive actions, and errors.
- **Gray** communicates empty, unavailable, muted, or secondary states.

Color never carries meaning alone. Labels, icons, text, shape, and accessible state attributes reinforce it.

## Typography

Use a clear modern sans-serif with strong numeric legibility. Headings are confident and compact. Labels are concise. Status text uses sentence case. Technical diagnostics may use a monospace face. Avoid novelty type in control surfaces.

## Spacing and layout

Use a consistent spacing scale based on 4, 8, 12, 16, 24, and 32 pixels. Dense performance tools may use tighter spacing while preserving touch targets. Primary work areas remain visually dominant. Sidebars browse, inspectors edit, and toolbars control the current workspace.

## Components

- **Cards** group one concept and avoid unnecessary nesting.
- **Panels** establish durable workspace regions and use clear headings.
- **Primary buttons** perform the main committed action.
- **Secondary buttons** support transport, preview, navigation, and editing.
- **AI buttons** open or create candidates, never silently apply them.
- **Danger buttons** stop, clear, remove, or perform destructive actions.
- **Icons** supplement labels and follow one consistent family.

## Motion

Motion confirms state changes, playback, key presses, pad hits, playheads, and successful drops. It remains subtle, avoids blocking input, and respects reduced-motion preferences.

## Interaction rules

Focus is visible. Touch targets are generous. Disabled controls explain why. Hover is supplementary, not required. Recording and active playback remain visible when the user navigates elsewhere.
